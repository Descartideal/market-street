# 十万人市场与独显实测（2026-10-07）

本次在用户电脑上实际检测和运行，不是根据型号推测支持加速。硬件为 NVIDIA GeForce RTX 5070 Laptop GPU，CUDA 可见显存 8,150 MiB，计算能力 12.0；驱动 581.29，CUDA Toolkit 13.0。同时存在 Intel 核显，计算后端选择非集成 CUDA 设备，明确返回 NVIDIA 型号。`nvidia-smi` 的计算进程列表也出现了本项目的 Python 工作进程。

实现采用 NVIDIA Driver API + NVRTC，在独显上运行本项目 `cuda-risk.cu` 内核。Python 仅负责标准库调用 DLL、传输数据和启动内核，不在 Python 中模拟 GPU；无需安装 CuPy 或 PyTorch。设备读取、上下文建立、设备内存分配、双向拷贝、内核执行及同步任一失败，都会明确显示 CPU 回退/独显不可用。

## 做了什么优化

- 订单簿从逐笔全量筛选/排序改为价格与时间堆，按所有者索引撤单，增量记录冻结美元/股数，按到期堆释放订单。
- GPU 并行计算每个 NPC 的 64 条八刻风险路径。正收益情景占比用于融资门槛，下行压力调整下单资金比例；输入来自当前信念与已完成历史，不使用未来行情。CPU 和 CUDA 使用同一哈希样本、双精度公式；关闭融合乘加保证对照一致。
- NPC 撮合改为先速度派首批、后普通批次（含速度派第二次），每批由五个 CPU 工作线程按股票分区并行计算。借款和撤单决策完成后，冻结本批资金与股份；线程只返回成交计划，主账本统一结算。同股冲突订单仍按价格/时间优先，自成交跳过；玩家 C++ 接口仍同步执行。
- 传输使用可转移二进制数组；工作线程仅维护轻量价格堆，不建立无用账户/过期索引。每批成交后清理失效堆节点，避免盘口遍历扫过大量已成交订单。网页明确显示五股工作线程或 CPU 单线程故障回退。
- 网页状态只发送近端订单、完整五档聚合量和 200 名 NPC；排行由服务器分页，图鉴每页 200 人。全量公开资料和归档仍可通过 SDK 分页/全部查询，不删掉参与者或交易历史来伪装十万人。

## 同版 CPU / CUDA 对照

命令：

```shell
node market-game/strategies/benchmark-scale.cjs
```

本次包含修复后的分析派目标仓位策略、公司经营、经济波动、分红、真实借股做空和八种分析派，仍按最新成交价融资，无抵押折扣。随机种子 42；每种规模创建完全一致的 CPU/CUDA 市场；先预热 2 刻，再交错测量 12 刻，覆盖第 12 刻分红。不启动玩家 C++ 程序。每刻校验全部挂单、每个 NPC 的现金、持仓、美元债务、空头、借出股份和空头成本、五股价格相同；结束时还核对公司状态、经济历史和借股库存；压力情景的最大数值差为 0。

| NPC 数 | CPU 回合中位数 | CUDA 回合中位数 | CPU 完整返回中位数 | CUDA 完整返回中位数 |
|---:|---:|---:|---:|---:|
| 5,000 | 33.12 ms | 24.23 ms | 34.61 ms | 25.78 ms |
| 100,000 | 858.14 ms | 667.80 ms | 911.98 ms | 703.17 ms |

“回合”包含开刻、收入/利息、NPC 策略和真实撮合；“完整返回”还包含构建网页状态，不包含浏览器绘制或玩家程序耗时。两种后端均使用五股并行撮合；本版 CUDA 风险计算使十万人整体回合约 1.29 倍提速，5,000 人约 1.37 倍。时间随电源模式、温度、订单深度和参与者状态变化，首次初始化/首刻可能更慢。

十万人同一批风险输入：CPU 180.50 ms；CUDA 内核及设备拷贝 4.91 ms；含 Node/Python 通信 14.96 ms，约 12.07 倍。这个倍数只适用于风险计算，不能标成整个市场提速。

改造前提交 `4f37e69` 的 5,000 人首刻实测 1,406.38 ms；仅换成订单索引、仍使用旧经济机制时，首刻约 35.38 ms，随后四刻约 12.87–20.63 ms。新旧市场策略和资金分布不同，这组数据用于定位扫描/排序瓶颈，不当作纯 GPU 的公平对照。

第 14 刻时，5,000 人累计公司分红 $20,494.4375，十万人 $337,179.9310。此次默认利率两组无 NPC 空头持仓，仍核对空头字段；实际开空/归还由专项测试覆盖。新增大盘历史、全市场现金和债务汇总逐刻 CPU/CUDA 一致性检查。

原始逐刻数据：[scale-benchmark-results.json](../market-game/strategies/scale-benchmark-results.json)。测试脚本会重新生成该文件，并强制要求真正的非集成 CUDA 设备；无独显不能报告通过。

## 撮合并发实测

运行 `node market-game/strategies/test-parallel-leverage.cjs`。实际创建五个 Node 工作线程，固定负载每股 12,000 笔原挂单与 4,000 笔新单，五股共 20,000 笔成交；检查线程开始/结束区间，10 对线程存在计算时间重叠。当前单次负载并行墙钟 19.00 ms、同算法单线程 25.56 ms。这个较小负载存在传输和调度开销，并行不保证比单线程更快；不把线程数量当作提速倍数。原始记录：[parallel-benchmark-results.json](../market-game/strategies/parallel-benchmark-results.json)。

另以独立原逐单撮合实现对照价格、数量和成交双方，测试跳过自成交、跨股资金冻结、线程故障 CPU 回退，以及 5,000 人连续八刻两种执行方式的逐笔成交、订单、现金、负债和股份相同。市场同批决策读批次开始盘口，不读同批成交，因而与旧版逐个决策/立即成交的价格路径不同；旧版提交 `38eee89` 的性能不是本版机制的公平串并行对照。

## 开启与诊断

双击 BAT，创建市场时选「自动 · 优先独显 CUDA」或「必须使用独显 CUDA」。本机已实际跑通。其他电脑需要 NVIDIA CUDA 独显、兼容驱动、CUDA Toolkit 的 NVRTC 和 Python 3.9+；普通 CPU 游戏只需要 Node.js 22+。

若 Python 不在 PATH，可设置 `MARKET_PYTHON` 为完整可执行路径；CUDA 安装可通过 `CUDA_PATH` 定位。网页开局显示检测结果，导航栏显示真正执行该刻的后端、设备与耗时。自动模式失败会显式回退 CPU；强制模式在不可用时拒绝开局，运行中故障会明确提示本刻 CPU 收尾，不伪装为 GPU。

十万人分布抽样（种子 42）：初始净资产中位数 $1,880.32，90 分位 $7,399.80，99 分位 $49,117.94，最大 $9,999,769.51；约 86.9% 普通 NPC 没有融资意愿。它是游戏用截断幂律模型，不是某国财富调查。

## 已完成验证

资金/股票守恒、同价时间优先、自成交跳过、订单释放、历史封存、玩家与 NPC 的真实买盘强平；正负利率/资金边界；借股与归还的股份守恒、部分成交后归还未卖出股份、空头分红补偿与真实卖盘平仓、公司私有数据隔离、C++ 实际开空平空；按资金扩大股数；选择性融资与不借款人群；速度派每刻两次机会；十万人 CPU/CUDA 结果一致；真实 C++23 接口、停机/超时、资金流水与 UTF-8 输出；网页开局、回合、排行和图鉴翻页。

订单数据与行情完整留在本局内存，长时间运行十万人市场会持续增加内存占用；目前没有磁盘存档。性能报告测的是前十四刻，不能代替数千刻的内存压力测试。
